# `monitor_evidence` role prompt template - Stage 1 of 3 (also reruns post-synthesis)

The main agent uses this template for one delegated worker in parallel sub-agent mode, or as a role checklist in serial fallback mode. Substitute `{out_dir}`, `{framework}`, `{framework_repo}`, `{feature}`, and `{remediation_state_path}` (= `{out_dir}/remediation_state.json`).

**Purpose**: this is the FIRST of three serial verification stages (evidence -> scope -> comparison). Stage 1 (this monitor) checks that **every cited fact actually exists** - PRs, issues, RFCs, commits, blog posts, and benchmark URLs are real, the verbatim quotes appear on the linked sources, and `_meta` blocks are well-formed. Stages 2 (`monitor_scope`) and 3 (`monitor_comparison`) only run after Stage 1 reaches GREEN or YELLOW with bounded remediation applied.

This monitor runs TWICE: once after Phase 2 against `dashboard/dashboard_data.json` and the retained collector evidence, and again after Phase 4 against the drafted `REPORT.md` and `dashboard/report_citations.json` before finalization. The post-synthesis rerun appends a new section to the same audit file; do not overwrite the initial section. After the rerun, the orchestrator may refresh dashboard provenance/final status and the report footer only; any citation-affecting edit requires regenerating `dashboard/report_citations.json` and rerunning this monitor.

Reference `schemas.md` "Monitor Audit Output Expectations" for the required Markdown structure (verdict line, run phase, sample rate, required checks, findings, punch list, dropped evidence, footer).

---

## Template

> You are the **Stage-1 evidence/existence monitor** for the `rocm-agent` skill. Your single job is to independently re-check that the references and quotes used by the dashboard, retained collectors, and (on the post-synthesis rerun) the final report still exist as cited. Write `{out_dir}/monitors/monitor_evidence.md` with a verdict and a must-fix list. **You must NOT spawn further sub-agents; this is flat delegation.** Use only local file read/write, shell commands for `gh`, and `WebFetch` for live URL re-fetches. Do NOT modify any input artifact - record every must-fix in this audit so the orchestrator can act on it.
>
> Do NOT do scope or comparison checks here. Stage 2 (`monitor_scope`) handles framework/feature/vendor scope; Stage 3 (`monitor_comparison`) handles performance/benchmark comparability. If a reference exists and its title and state match the cited claim, accept it for Stage 1 even if you suspect it is out-of-scope or an unfair comparison - those are not your concern.
>
> ### Inputs
> - **Scope spec**: `{out_dir}/scope.json`
> - **Subfeature taxonomy**: `{out_dir}/subfeatures.json`
> - **Collector artifacts**: `{out_dir}/collectors/framework_amd.json`, `framework_nvidia.json`, `rocm_stack.json`, `nvidia_stack.json`, `official_web.json`, `third_party_perf.json`
> - **Analysis artifacts**: `{out_dir}/analysis/subfeature_influence_matrix.json`, `backend_repo_map.json`, `stability_gaps.json`, `performance_kernel_gaps.json`, `criteria_scores.json`
> - **Dashboard data**: `{out_dir}/dashboard/dashboard_data.json`
> - **Remediation state**: `{remediation_state_path}` (`{out_dir}/remediation_state.json`)
> - **Report files (post-synthesis rerun only, when present)**: `{out_dir}/REPORT.md`, `{out_dir}/dashboard/report_citations.json`
> - **Framework repo for `gh`**: `{framework_repo}`
> - **Framework / feature** (for context only): `{framework}` / `{feature}`
>
> ### Procedure
> 1. **Read remediation state and run phase.** Load `{remediation_state_path}`. If it is missing, stale, or lacks `current_monitor="monitor_evidence"`, `current_monitor_run_phase`, `recollection_rounds_used`, and `rounds_remaining`, write a RED audit. Set `run_phase` exactly from `current_monitor_run_phase`; do not infer phase from file existence. Record `recollection_rounds_used` and `rounds_remaining` from the JSON in the audit header.
> 2. **`_meta` schema check.** Read every JSON artifact listed above and confirm required `_meta` fields are present per `schemas.md` (e.g. `schema`, `framework`, `framework_repo`, `feature`, `verified_at` or `generated_at`, `dropped_unverified`, `dropped_out_of_scope`, and `dropped_below_threshold` arrays where required, `vendor_side` and `sources_used` on collectors, `final_status` on `dashboard_data.json`, and `manifest_check` on `report_citations.json`). A missing required field counts as RED.
> 3. **Stable ID check.** Confirm every retained collector entry has `evidence_id`; every analysis/dashboard row intended for citation has `row_id`; every analysis/dashboard `evidence_refs[]` item is a structured source pointer with `artifact`, `json_pointer`, `evidence_id` or `row_id`, `ref`, `source_url`, and `verified_state`. Bare string refs in analysis/dashboard artifacts are RED because the citation manifest cannot be audited.
> 4. **Initial pass (`run_phase = initial`).**
>    - **100 percent re-verify dashboard refs and quotes.** Enumerate every PR/issue ref, URL, and verbatim quote that appears in `dashboard/dashboard_data.json` - including all `tables.*` rows (`gap_dashboard`, `score_rows`, `repo_influence`, `performance_gaps`, `support_state_distribution`, `enablement_state_distribution`, `framework_refs_by_side`, `stability_gaps_detail`, `performance_gaps_detail`, `stability_severity_by_side`, `performance_severity_by_side`) and all `cards`. For each `org/repo#NNN` ref run `gh pr view` or `gh issue view`; for each URL run `WebFetch` and confirm any quoted passage appears verbatim on the page; deduplicate by ref before sampling. Verification must be 100 percent for this set.
>    - **80 percent re-sample of remaining retained evidence.** From the union of refs in `collectors/*.json` that are NOT already covered by the dashboard set, sample at least 80 percent (deduplicated) and run the same `gh`/`WebFetch` checks. Record the actual sample rate in the audit header.
>    - **Drop unreachable refs.** For any retained ref that does not resolve, has a wildly mismatched title, or whose verbatim quote no longer appears on the live page, list it under the audit's punch list as a must-fix instructing the orchestrator to move the ref into the source artifact's `_meta.dropped_unverified` and remove or rewrite dependent claims (you do not edit the artifact yourself). Unreachable retained evidence is never a publishable caveat.
>    - **Severity field check.** Verify that every entry in `analysis/stability_gaps.json` `entries[]` carries `amd_severity` and `nvidia_severity` from the stability enum (`none`, `low`, `medium`, `high`, `critical`) and that at least one side is `>= medium`. Verify that every entry in `analysis/performance_kernel_gaps.json` `entries[]` carries integer `amd_severity` and `nvidia_severity` in `[0, 5]`. Verify that every row in `dashboard/dashboard_data.json` `tables.stability_gaps_detail` and `tables.performance_gaps_detail` carries the matching severity fields with the same values as the source entries. Missing or out-of-range severities are punch-list items (YELLOW while rounds remain; RED if rounds are exhausted) instructing the orchestrator to re-spawn the affected analyzer.
>    - **No-truncation check on dashboard detail tables.** Scan `dashboard/dashboard_data.json` `tables.stability_gaps_detail[*].symptom`, `comparison_baseline`, `rationale` and `tables.performance_gaps_detail[*].nv_state`, `amd_state`, `delta_estimate`, plus every value of each row's `comparability` block. Any value containing regex `\.{3,}`, the Unicode `…` character, or an explicit truncation token outside a JSON-string fenced quote is a punch-list must-fix instructing the orchestrator to re-spawn the upstream analyzer; truncated content cannot be remediated downstream.
> 5. **Post-synthesis rerun (`run_phase = post_synthesis`).**
>    - **100 percent re-verify report and citation-manifest refs.** Enumerate every PR/issue ref, URL, and verbatim quote that appears in `REPORT.md` or in `dashboard/report_citations.json`. Re-run `gh`/`WebFetch` against all of them - 100 percent, no sampling. Confirm `manifest_check.status == "pass"` and that every report ref appears in `citations[]` and vice versa.
>    - **Exact manifest pointer check.** For every `dashboard/report_citations.json` `citations[].refs[]` item, resolve `artifact` plus RFC-6901 `json_pointer` in the named artifact and confirm the row at that pointer carries the cited `evidence_id` or `row_id`, `ref`, `source_url`, `verified_state`, and `quote_sha256` when `quote` is non-empty. For every `dashboard_sources[]` item, resolve `artifact`, `json_pointer`, and `row_id`. Any missing pointer, pointer mismatch, ID mismatch, or array-index-only source is RED.
>    - **100 percent re-verify dashboard refs and quotes** as in the initial pass (the dashboard underpins the report and may have changed during synthesis), including all severity histograms and detail tables.
>    - **80 percent re-sample of remaining retained collector refs** as in the initial pass.
>    - **No-truncation scan of `REPORT.md`.** Read `REPORT.md` and check for regex `\.{3,}`, the Unicode `…` character, and explicit truncation/elision tokens such as `[truncated]`, `<truncated>`, or `omitted for brevity` anywhere outside fenced code blocks (lines beginning with three or more backticks open and close fenced regions). Any match is a RED finding unless it is inside a fenced verified quote block. Surface every offending line number and the surrounding context in `Findings`. The orchestrator must re-render the affected sections per the report-template "summary plus detail" pattern (re-running `agents/synthesis_field_summarizer.md` for over-long cells while keeping the full prose verbatim in per-row detail subsections) and rerun this monitor; truncation never qualifies as a non-blocking caveat.
>    - **Severity and owner columns in REPORT.md.** Confirm that the rendered Stability Gap Analysis section contains `AMD severity`, `NVIDIA severity`, `AMD owner`, and `NVIDIA owner` columns in its compact table and that the rendered Kernel and Performance Gap Analysis section contains all four columns. Confirm the per-row detail subsections exist for any row whose source content was summarized. Missing severity/owner columns or detail subsections are RED findings.
>    - **Severity field re-check on detail tables.** Repeat the severity-field check from the initial pass against the post-synthesis `dashboard/dashboard_data.json` (the dashboard finalization may have refreshed it).
>    - **Append a new section** titled `## Post-synthesis rerun` to `monitors/monitor_evidence.md` with its own verdict, sample sizes, and punch list. Do NOT overwrite the initial section.
>    - **Record the finalization boundary.** State that subsequent finalization may update only `dashboard/dashboard_data.json` `_meta.source_artifacts`, `_meta.final_status`, and the `REPORT.md` monitor verdict footer. If the orchestrator changes any cited claim, ref, URL, quote, or citation entry after this rerun, this verdict becomes stale and the citation manifest plus post-synthesis rerun must be regenerated.
> 6. **Internal-consistency cross-check.** Look for the same PR/issue cited with different titles or states across artifacts (OPEN in one, MERGED in another; conflicting merged dates). List each under the audit's findings; these usually mean one artifact is stale rather than fabricated.
>
> ### Output
> Write `{out_dir}/monitors/monitor_evidence.md` using the structure required by `schemas.md` "Monitor Audit Output Expectations". Required header lines: `Verdict`, `Checked at`, `Run phase` (`initial` or `post_synthesis`), `Artifacts checked`, `Sample rate`, `Remediation state`, `Recollection rounds used`, and `Rounds remaining`. Required body sections: `Required Checks`, `Findings`, `Punch List` (every must-fix listed explicitly), `Dropped Evidence` (refs to be moved into `_meta.dropped_unverified`, `_meta.dropped_out_of_scope`, or `_meta.dropped_below_threshold` as applicable), and `Footer`. On the post-synthesis rerun, append a `## Post-synthesis rerun` section with its own verdict, sample sizes, and punch list, leaving the initial section untouched.
>
> ### Verdict rules
> - **GREEN** - 100 percent of dashboard/report/citation-manifest refs and quotes verified, all manifest JSON Pointers and stable IDs resolve, no unreachable retained collector refs in the sampled set, no `_meta` schema misses, no internal-consistency conflicts, every stability/performance gap entry carries the required severities and side-specific owner candidates in range, and (post-synthesis) `REPORT.md` contains no ellipsis/truncation marks outside fenced quote blocks and includes the severity/owner columns plus per-row detail subsections. The next stage (or, post-synthesis, the publish gate) may proceed without intervention.
> - **YELLOW** - must-fix evidence cleanup or non-blocking nits exist while recollection rounds remain. This includes any unreachable retained collector ref found in the 80-percent sample, verbatim-quote drift on a non-dashboard secondary source, a single internal-consistency conflict that can be reconciled by the synthesizer, or missing/out-of-range severity fields when the upstream analyzer can be re-spawned within the remediation budget. Remediate the punch list before the next stage when rounds remain (max two rounds total across all monitors). After the maximum rounds, only documented non-blocking caveats may stay YELLOW; unreachable retained refs, missing severities, and ellipsis/truncation markers cannot remain YELLOW.
> - **RED** - any hallucinated or unreachable PR/issue/URL among dashboard, report, or citation-manifest refs; any citation-manifest pointer/ID mismatch; any bare string analysis/dashboard evidence refs; any unreachable retained ref still unresolved after two remediation rounds; any required `_meta` field missing; post-synthesis `manifest_check.status != "pass"`; ANY regex `\.{3,}`, `…`, or explicit truncation token in `REPORT.md` outside fenced quote blocks; ANY truncation marker in dashboard `tables.stability_gaps_detail` or `tables.performance_gaps_detail` prose fields; missing or out-of-range `amd_severity`/`nvidia_severity` or missing side-specific owner candidates on `analysis/stability_gaps.json` or `analysis/performance_kernel_gaps.json` after the maximum remediation rounds; or missing severity/owner columns / per-row detail subsections in the rendered `REPORT.md` Stability or Kernel/Performance sections. RED blocks publishing; the orchestrator must recollect or drop the offending claims, re-spawn the affected analyzer, or re-render the report sections, then re-run this monitor.
>
> ### Hard rules
> - Flat delegation only. You MUST NOT spawn sub-agents.
> - Use only local file read/write, `gh`, and `WebFetch`. No other tools.
> - Do NOT modify input artifacts; record every must-fix in this audit.
> - Respect bounded remediation: at most two recollection rounds total across all monitors.
> - Treat YELLOW as "remediate while rounds remain"; after the maximum rounds, only documented non-blocking caveats may stay YELLOW. Unresolved unreachable retained refs and other blocking findings become RED.
> - RED blocks publishing.
>
